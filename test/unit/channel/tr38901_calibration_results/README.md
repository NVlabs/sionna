# TR 38.901 Calibration Assets

This directory contains self-contained calibration data for the manually
runnable script `../tr38901_calibration.py`.

The generator always instantiates TR 38.901 V16.1 channel models. Phase 1,
Phase 2 Config 1, and Phase 2 Config 2 are compared with Release-14-era
baseline reference curves for UMi, UMa, and InH. The blockage and
spatial-consistency references are likewise from the V14 additional-feature
calibration workbooks for Tables 7.8-5 and 7.8-6, currently for UMi at 30 GHz.
The bundled spatial-consistency Config2 calibration covers only the static CDF
metrics, not the dynamic varying-rate metrics. The normative `InF` profile
uses the V16.1 Table 7.8-7 10 m hall.

- `reference_curves.json` stores static digitized curves from the named 3GPP
  calibration workbooks. The repository records workbook filenames and
  contribution identifiers, but does not contain the source binaries,
  retrieval URLs, source checksums, or extraction tooling.
- `cdfs/` stores Sionna-generated CDF and line-curve JSON files.
- `figures/` stores plots regenerated by `plot_tr38901_calibration.py`.

The InH reference curves predate the final V16.1 Indoor-Office parameter
tables. ASA, ASD, ZSA, and several related cluster parameters changed
significantly, so visible offsets in the V16.1 InH angular-spread curves are
expected and are not a conformance failure.

## Reproducing the generated bundle

The device-aware tests in `../test_3gpp_calibration_regression.py` compare
reduced V16.1 workloads, including Config2, with prior Sionna-generated
snapshots in `cdfs/`. These are regression snapshots, not independent 3GPP
references or conformance evidence. They use statistical tolerances so
equivalent distributions can pass across CPU, CUDA, and PyTorch versions.
Driver tests separately check analytic metric semantics and profile metadata;
`../test_3gpp_calibration_reference.py` validates the external reference data
and its recorded provenance.

Run the following command from the Sionna repository root:

```bash
python test/unit/channel/tr38901_calibration.py \
    --phases phase1 config1 config2 inf \
        blockage_model_a blockage_model_b \
        spatial_consistency_metric1_2 \
        spatial_consistency_metric3_6 \
        spatial_consistency_config2_metric1_2 \
    --phase1-num-batches 100 \
    --phase2-num-batches 100 \
    --batch-size 1 \
    --phase1-uts-per-sector 16 \
    --phase2-uts-per-sector 1 \
    --spatial-metric1-2-num-ut-per-sector 20 \
    --spatial-metric1-2-num-drops 100 \
    --spatial-metric1-2-ut-chunk-size 128 \
    --spatial-metric3-6-num-ut-per-sector 200 \
    --spatial-metric3-6-num-drops 20 \
    --inf-num-batches 5 \
    --inf-uts-per-bs 90 \
    --inf-ut-chunk-size 256 \
    --seed 1234 \
    --precision single \
    --clean
```

The driver uses all visible CUDA devices by default, with one spawned worker
per device and independent scenario/frequency/phase runs executing
concurrently. Request index `i` is statically assigned to device index
`i % num_devices`; completion timing cannot alter the assignment. Use
`--devices` to restrict execution to a subset such as `--devices cuda:0`, or
use `--devices cpu` on a machine without CUDA. Each result and manifest run
records its assigned device. Sionna uses device-specific deterministic random
streams, so exact samples are reproducible for the recorded assignment but can
differ when a run moves to another GPU.

A complete run produces 46 result JSON files, 46 entries in
`manifest.json` under `runs`, and 18 figures. Phase-specific workload fields
in each result's `metadata` are mirrored in `runs.<key>.workload`; the
top-level manifest fields record the invocation arguments. These records must
agree. Always use `--clean` for full regeneration, because otherwise existing
CDF files can be retained and indexed as part of the new manifest.

For spatial-consistency metric 3/6, Sionna bins distinct UT pairs by distance
intervals `[d,d+1) m`; the plotted `0 m` point therefore corresponds to the
`[0,1) m` bin, not exact self-correlation. For blockage Model B, RSRP is
computed from the coherent CIR after per-ray amplitude blockage losses and then
averaged in linear power over CDL-E ray-coupling realizations.

For spatial-consistency Config2 metric 1/2, Sionna stores the required
noise-inclusive result as `wideband_sinr`. The public workbook contains
interference-only company SIR submissions with a large spread; those curves
are preserved only under `historical_wideband_sir`. The dynamic varying-rate
Config2 metrics are not generated.

All newly generated `coupling_loss` values are positive losses. Negative
workbook-compatible values are separately named `historical_path_gain`; the
static reference JSON preserves its negative arrays under that key without a
numeric sign transformation.

For InF, the public R1-1909704 workbook used 25 m hall height for
sparse-clutter sub-scenarios, 15 m for dense-clutter sub-scenarios, and
pre-final delay-spread assumptions. Its curves are therefore not bundled or
overlaid as direct references for the normative V16.1 Table 7.8-7 10 m `inf`
profile.
